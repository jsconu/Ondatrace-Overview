Long-term memory that doesn't leak

Most AI agents and scheduled AI tasks have a leaky-bucket memory. Each run can only hold so much text, so they carry forward a summary of what came before. Every summary drops details. A few weeks later, the date a salesperson promised or the risk someone raised in a meeting is gone. Ondatrace keeps a long-term memory built for project work.

Stored as records

Projects, dates, decisions, risks and promises are each kept as their own record, with a link to where they came from.

Updated without losing detail

Each check reads only what changed and updates those records. Older facts stay exactly as they were recorded.

History you can use

It can tell you that a go-live date has moved three times, or that a risk has been open for six weeks.

How it's different from AI agents and scheduled jobs

General AI agents and scheduled AI jobs can read your tools and run on a timer. They don't keep a lasting memory of your projects, and they don't judge them the same way every time. Instead of each project manager building their own agents and fine-tuning scheduled jobs and risk rules, Ondatrace runs it all for the whole PMO from one setup.

More detail

The six ideas behind the agent
  1. Start from what happened. Updates from your tools record who, when and which project, so they can build up a history.
  2. Rules decide, AI explains. Did a date move? Is a blocker still open? When a rule can decide, it does.
  3. Remember what came before. Whether a problem is new or has been getting worse for weeks matters as much as today's status.
  4. End with a decision. Decisions, risks and dependencies each get their own record, so they don't get lost in a status paragraph.
  5. Earn trust one action at a time. It takes on low-stakes work first, like refreshing data, long before anything like messaging a customer.
  6. Work out the structure first. It suggests which projects exist and how they link, and people confirm. You don't need to set anything up first.

We'd count Ondatrace as a failure if the people using it find that:

  • Seeing across tools tells them little beyond what their tools already show.
  • Its suggestions are too noisy to be worth a manager's time.
  • The evidence is there but too hard to check.
  • Its review list becomes another inbox nobody trusts.
  • It can't explain why it did something, or why it didn't.
  • Fixing and supervising it takes more time than it saves.
Design decisions

Each choice below helps keep findings accurate and people in control.

Evidence and trust

  • Rules set project health before AI writes about it. The same facts should give the same answer every time.
  • Every finding keeps its sources. Leaders can check the evidence instead of taking the AI's word.
  • A risk stays open until something closes it. Teams often stop mentioning problems they haven't solved.
  • Automation settings never change the facts. How much it does on its own shouldn't change what's true.

People stay in charge

  • Moving a promised milestone needs a person. A milestone is a promise, and moving it has effects outside the project.
  • The AI suggests actions but can't authorize them. How confident it sounds never decides what it's allowed to do.

Reliability and security

  • The application controls access. Instructions given to an AI are not a security control.
  • Work only when something changed. A quiet project shouldn't cost more or send new alerts because a day passed. An overdue milestone counts as a change.
  • One failure doesn't stop the rest. If one tool connection fails, the others keep going.
